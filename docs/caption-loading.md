# 页面刚加载时的字幕获取

首次总结或启用双语字幕时，如果页面的 API 配置、播放器响应或字幕轨道尚未准备好，不能把单次失败直接当成“视频没有字幕”。

1.4.3 原始流程：已捕获缓存 → InnerTube ANDROID（1 次 player POST，JSON3/XML 最多 2 次字幕 GET）→ 页面轨道（JSON3/XML 最多 2 次字幕 GET）→ 播放器最多两轮加载。全路径失败可能产生 1 次元数据 POST、4 次直接字幕 GET，再加播放器加载及恢复原轨道时的请求。这条链在 1.4.2 已存在，并非 1.4.3 新增。总结和双语字幕的并发任务已有共享，但不能避免一次任务内部的多路径请求。

当前获取顺序：MAIN world 等待完整轨道列表并选轨 → 同轨道已捕获响应 → 等待仍在途的原生请求 → 必要时触发播放器加载。删除 ANDROID player 请求和直接 JSON3/XML 探测；解析 JSON3 或 XML 都使用已返回的正文，不为切换格式另发请求。

字幕选择规则：

1. 优先匹配播放器当前音轨的语言。通过 `getAudioTrack().getLanguageInfo()`（存在时）读取当前音轨的语言信息；兼容直接语言字段或语言形式的音轨 ID（例如 `en.4`）；不可用时读取当前视频播放器响应中的默认/唯一音轨信息。当前音轨 ID 已知但无法解析时，不擅自改用另一个默认音轨。音轨关联字幕索引仅在语言一致、无歧义时作为线索，不把默认字幕语言直接认定为音轨语言。
2. 音轨数据缺失、无法判断，或没有同语言字幕时，匹配用户指定的「优先获取的字幕语言」。该设置默认 `en`，与界面和 AI 输出语言独立；设置页提供现有语言建议，也可直接输入 `ar` 等合法语言代码。修改后清空当前页面字幕、分段和译文状态，下一次获取重新选轨；开启双语字幕时自动重新加载。已显示或正在生成的 AI 总结不受影响，正在生成时推迟到生成结束后再生效（此前会中止所有标签页里进行中的总结）。
3. 两者都没有匹配时，使用 YouTube 返回数组中的第一条有效字幕，不再全局优先人工或英语。同一种匹配语言内仍优先人工字幕；语言精确匹配优先于地区变体匹配，中文文字体系不自动互换。
4. 不分析音频，不新增音轨识别或播放器信息网络请求。自动字幕可能属于配音音轨，因此跟随当前音轨，不声称识别原声。带 `tlang` 的自动翻译响应继续排除。

播放器通过已有 `caption-main.ts` 入口实现，无需新增扩展权限：

1. 最多等待 8 秒，让当前视频的播放器 API 和字幕轨道就绪；不接受旧视频的 player response。整个 MAIN world 加载共用 15 秒预算（`CAPTION_LOAD_BUDGET_MS`），隔离世界桥接上限 18 秒（`PLAYER_CAPTION_BRIDGE_TIMEOUT_MS`），两者须同步修改，保证隔离世界不会在 MAIN world 仍在工作时先放弃。
2. 按下述规则选轨后，优先复用 MAIN world 最近 5 分钟的同视频、同语言、同轨道类型响应（最多保留 12 条）。这也覆盖响应先于 ISOLATED world 注册监听器的情形。
3. 同时观察 fetch/XHR 的请求开始与完成（fetch 在正文读完并交给监听器后才算完成），给原生启动请求 300 毫秒窗口。若有匹配的**在途**请求，最多等待约 6 秒，请求结束即进入下一步。已结束但没有可用字幕的请求（早期空结构、HTTP 错误）不再阻塞加载——1.4.7 及之前会把这类请求视为“已有请求”30 秒，期间只被动等待直到超时，用户只能手动开 CC，这是“需要手动点一下”的主因。
4. 没有匹配请求时，保存原轨道、临时隐藏字幕并加载字幕模块。给模块 150 毫秒启动请求；模块已发出目标请求时不再重复选轨。否则选择目标轨道。
5. 每次桥接最多两轮选轨，每轮最多产生一个匹配请求：第二轮覆盖“模块尚未就绪、没有发出请求”和“请求返回空正文或错误”两种情况；仍在途的慢请求不会被重新选轨打断。每个视频 2 分钟内插件最多主动触发 4 次，防止反复重试变成请求风暴。
5a. 只有真实用户输入才算“用户更改”：点击 CC 按钮、字幕设置菜单或按 `c` 键。播放器自己切换轨道（外语视频自动开字幕、`loadModule` 恢复上次语言）不再被误判为用户操作；加载开始前播放器的自发切换会成为结束后恢复的基准。1.4.7 及之前根据 `getOption` 的任何变化判定用户更改，浏览器实测中会在无人操作时报 `user-changed-captions`。
6. 在成功、超时或异常时清理监听器和隐藏样式，并恢复原轨道；原本已启用同一轨道时不重复写回。用户期间主动切换 CC 或改选语言时保留用户选择；导航后不把旧视频设置写回新播放器。
7. 失败原因映射为不同提示：`not-ready`（播放器未就绪）、`timeout`（加载超时）、`user-changed-captions`（获取期间字幕设置被更改）、`no-captions`（视频无字幕），不再统一显示“请手动开启 CC”。
8. 双语字幕自动加载失败后，MAIN world 捕获到同视频的有效字幕时派发不带正文的 `vas-caption-available`，隔离世界据此自动重试一次（命中 MAIN-world 缓存，不产生新请求）。用户事后手动开 CC 后无需再点插件。
9. 观察到原生字幕 HTTP 429 时报告异常并停止探测，遵守 Retry-After（秒数或 HTTP 日期），缺失或无效时默认冷却 60 秒。该冷却仅保存在当前页面内，不跨标签页或刷新共享，也不会拦截 YouTube 自己发起的请求。

请求数口径：修复后插件自身不再直接 fetch 字幕或 player 元数据。模拟冷启动、CC 关闭时，播放器发出 1 次字幕请求；有缓存或在途请求时新增 0 次。此数字不是所有真实 YouTube 页面的硬上限：播放器内部行为由 YouTube 控制，原来启用其他语言时恢复原轨道也可能加载该语言。

总结和双语字幕共享同一视频的在途获取。缓存统一保留在 MAIN world，每次先根据完整轨道列表选择，再复用匹配结果；不再使用仅按视频或任意语言返回的 ISOLATED 缓存。普通失败后释放在途任务，下一次手动操作可以重新尝试。视频导航会取消桥接请求。ISOLATED world 桥接设有 16 秒上限，超过时通知 MAIN world 清理。这条路径依赖 YouTube 未公开的播放器方法；真实无字幕的视频不会因此获得语音转写能力。

自动化回归见 `src/content/caption-main.test.ts`：覆盖已结束空请求不阻塞加载、空响应只重试一次、每视频触发上限、播放器自发切换不算用户操作、当前/默认音轨、歧义与缺失数据兜底、用户指定语言及地区匹配、同语言人工优先、数组顺序兜底、设置独立保存和切换、错误语言/类型缓存排除、轨道变化后重新选择、冷启动请求计数、总结/字幕并发、缓存零新增请求、原生在途请求复用、模块自行请求去重、慢响应和空响应不重试、原生 429、页面/轨道延迟、早到响应、错误视频/语言、无字幕、模块异常、视频导航、用户字幕选择和桥接缺失。

清除本视频字幕与翻译缓存：

- 工具栏按钮同时删除本视频的持久化译文、页面内字幕/分段/译文状态，以及 MAIN world 保存的所有语言字幕响应和请求记录，随后按当前选轨规则重新获取字幕。
- 取消本视频正在进行的字幕桥接，丢弃清理前开始的 fetch/XHR 响应（含尚未读完的响应正文），防止迟到数据回填。其他视频的字幕缓存保留。
- 先等待旧翻译任务和已开始的存储写入结束，再删除持久化译文，避免旧写入恢复缓存。导航后不重置新视频的页面状态。
- 双语字幕开启时重新挂载并从当前播放位置翻译；重新获取失败时显示错误，下一次操作重新获取，不回用清除前的原文。
- 不删除 AI 总结缓存，不清理浏览器/YouTube 自身的网络缓存，也不取消 HTTP 429 冷却。若来源正在限流，重新获取仍会报告限流。

浏览器验收步骤：

- 在 `chrome://extensions` 重新加载指向本项目 `dist` 的开发版扩展，再刷新 YouTube 页面，使新的 document_start 脚本生效。
- 打开一个有字幕、尚无本地摘要缓存的视频，立即点击总结；确认自动等待后继续生成，不需要手动开关插件。
- 分别在 YouTube 原生 CC 开启、关闭时重复，确认处理完成后状态与原来一致。
- 开启插件双语字幕的同时点击总结，确认两者都得到字幕，且播放器不会反复切换 CC。
- 获取期间快速切到另一个视频，确认不出现前一个视频的字幕或摘要。
- 在等待期间手动切换 CC 或字幕语言，确认插件不会把设置强制改回。
- 打开真实无字幕的视频，确认等待有上限，之后显示无字幕提示。

本次修复在 Chrome for Testing 148（WSLg，加载 `dist`）中实测：修复前播放器早期请求返回空正文后插件只被动等待约 7 秒超时，SPA 切换时无人操作即报 `user-changed-captions`；修复后插件会主动重新加载一次、不再误判用户操作，失败在约 1.5 秒内给出具体原因。该自动化浏览器中 YouTube 对所有 timedtext 请求都返回空正文（与插件无关），因此“最终取到字幕”的成功路径仍需在日常使用的浏览器中确认。

音轨语言排查：1.4.7 只读取了音轨对象的直接字段，未兼容 `getLanguageInfo()`。当前实现优先读取该方法返回的 `languageCode` / `language` / `id`，并保留原有兼容分支。控制台 `[vas] Caption track selected` 输出视频 ID、读取到的音轨语言、用户指定语言及最终字幕语言，便于区分字段读取失败和选轨兜底；不会输出字幕正文或带签名的 URL。

真实页面验证（2026-11-04）：视频 `XXcGSMrurZs` 的当前音轨直接 `id` 是以 `251;` 开头的内部媒体标识，`getLanguageInfo()` 返回 `{name: "日语原始", id: "ja.4", isDefault: true, isAutoDubbed: false}`；字幕列表含日语和英语 ASR。将旧版和修复版实际选轨函数放在同一个真实播放器上对比，旧版结果为 `audio=null, caption=en`，修复后为 `audio=ja, caption=ja`。自动化回归已包含该返回结构。
播放器实际加载验证：通过原生播放器选中日语 ASR 后，捕获到了 `lang=ja, kind=asr` 的字幕响应，正文以「はい。…」开头；测试结束后恢复原字幕轨道。该验证未调用 AI，也未修改已安装扩展文件。
