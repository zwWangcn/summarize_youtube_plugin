# 页面刚加载时的字幕获取

首次总结或启用双语字幕时，如果页面的 API 配置、播放器响应或字幕轨道尚未准备好，不能把单次失败直接当成“视频没有字幕”。

当前获取顺序：已捕获字幕缓存 → InnerTube ANDROID 静默请求 → 页面字幕 URL → MAIN world 播放器加载兜底。成功的快速路径不会触发播放器字幕切换。单次静默网络请求设有 4 秒超时，避免请求卡住后无法进入兜底。

播放器兜底通过已有 `caption-main.ts` 入口实现，无需新增扩展权限：

1. 最多等待 8 秒，让当前视频的播放器 API 和字幕轨道就绪；不接受旧视频的 player response。
2. 优先复用 MAIN world 最近 30 秒的同视频、同语言、同轨道类型响应。这也覆盖响应先于 ISOLATED world 注册监听器的情形。
3. 没有可复用响应时，保存原字幕轨道，临时隐藏原生字幕，触发播放器加载选定轨道。
4. 观察 fetch 和 XHR 的 `/api/timedtext` 响应，要求视频、语言、轨道类型匹配，并排除 `tlang` 翻译轨道和空字幕。最多触发两次，每次等待约 3 秒。
5. 在成功、超时或异常时清理监听器和隐藏样式，并恢复原轨道。若用户期间主动切换 CC 或改选其他语言，则保留用户的选择。若已进入新视频，不把旧视频字幕设置写回新播放器。

总结和双语字幕共享同一视频的在途获取，失败后清除在途状态，下一次点击可以重新尝试。视频导航会取消桥接请求。ISOLATED world 桥接设有 16 秒上限，超过时也会通知 MAIN world 清理。

这条路径依赖 YouTube 未公开的播放器方法，仍需要浏览器回归；真实无字幕的视频不会因此获得语音转写能力。不同静默路径的等待会先于播放器兜底，因此 16 秒只是桥接上限，不是整次获取上限。

自动化回归见 `src/content/caption-main.test.ts`：通过模拟播放器、fetch/XHR、页面事件和假时钟，覆盖页面/轨道延迟、静默成功、并发获取、二次触发、早到响应、空响应、错误视频/语言、无字幕、模块异常、视频导航、用户字幕选择和桥接缺失。

浏览器验收步骤：

- 在 `chrome://extensions` 重新加载指向本项目 `dist` 的开发版扩展，再刷新 YouTube 页面，使新的 document_start 脚本生效。
- 打开一个有字幕、尚无本地摘要缓存的视频，立即点击总结；确认自动等待后继续生成，不需要手动开关插件。
- 分别在 YouTube 原生 CC 开启、关闭时重复，确认处理完成后状态与原来一致。
- 开启插件双语字幕的同时点击总结，确认两者都得到字幕，且播放器不会反复切换 CC。
- 获取期间快速切到另一个视频，确认不出现前一个视频的字幕或摘要。
- 在等待期间手动切换 CC 或字幕语言，确认插件不会把设置强制改回。
- 打开真实无字幕的视频，确认等待有上限，之后显示无字幕提示。

以上浏览器步骤尚未在本次环境中实际执行；自动化模拟通过不等同于所有真实 YouTube 页面均已验证。
