# 页面刚加载时的字幕获取

首次总结或启用双语字幕时，如果页面的 API 配置、播放器响应或字幕轨道尚未准备好，不能把单次失败直接当成“视频没有字幕”。

1.4.3 原始流程：已捕获缓存 → InnerTube ANDROID（1 次 player POST，JSON3/XML 最多 2 次字幕 GET）→ 页面轨道（JSON3/XML 最多 2 次字幕 GET）→ 播放器最多两轮加载。全路径失败可能产生 1 次元数据 POST、4 次直接字幕 GET，再加播放器加载及恢复原轨道时的请求。这条链在 1.4.2 已存在，并非 1.4.3 新增。总结和双语字幕的并发任务已有共享，但不能避免一次任务内部的多路径请求。

修复后的获取顺序：ISOLATED 缓存 / 最近 5 个视频的成功结果 → MAIN world 已捕获响应 → 等待已在途原生请求 → 必要时触发播放器加载。删除 ANDROID player 请求和直接 JSON3/XML 探测；解析 JSON3 或 XML 都使用已返回的正文，不为切换格式另发请求。

播放器通过已有 `caption-main.ts` 入口实现，无需新增扩展权限：

1. 最多等待 8 秒，让当前视频的播放器 API 和字幕轨道就绪；不接受旧视频的 player response。
2. 优先复用 MAIN world 最近 30 秒的同视频、同语言、同轨道类型响应。这也覆盖响应先于 ISOLATED world 注册监听器的情形。
3. 同时观察 fetch/XHR 的请求开始与完成，给原生启动请求 300 毫秒窗口。若已有匹配的在途或近期请求，最多等待约 6 秒，不重新切换字幕。
4. 没有匹配请求时，保存原轨道、临时隐藏字幕并加载字幕模块。给模块 150 毫秒启动请求；模块已发出目标请求时不再重复选轨。否则选择目标轨道。
5. 只在选轨后完全没有发出匹配网络请求时允许第二次选轨，以兼容模块尚未就绪。一旦发出过请求，即使返回空正文、错误或响应缓慢，都不自动重新选轨。
6. 在成功、超时或异常时清理监听器和隐藏样式，并恢复原轨道；原本已启用同一轨道时不重复写回。用户期间主动切换 CC 或改选语言时保留用户选择；导航后不把旧视频设置写回新播放器。
7. 观察到原生字幕 HTTP 429 时报告异常并停止探测，遵守 Retry-After（秒数或 HTTP 日期），缺失或无效时默认冷却 60 秒。该冷却仅保存在当前页面内，不跨标签页或刷新共享，也不会拦截 YouTube 自己发起的请求。

请求数口径：修复后插件自身不再直接 fetch 字幕或 player 元数据。模拟冷启动、CC 关闭时，播放器发出 1 次字幕请求；有缓存或在途请求时新增 0 次。此数字不是所有真实 YouTube 页面的硬上限：播放器内部行为由 YouTube 控制，原来启用其他语言时恢复原轨道也可能加载该语言。

总结和双语字幕共享同一视频的在途获取，并缓存成功结果。普通失败后释放在途任务，下一次手动操作可以重新尝试。视频导航会取消桥接请求。ISOLATED world 桥接设有 16 秒上限，超过时通知 MAIN world 清理。这条路径依赖 YouTube 未公开的播放器方法；真实无字幕的视频不会因此获得语音转写能力。

自动化回归见 `src/content/caption-main.test.ts`：覆盖冷启动请求计数、总结/字幕并发、缓存零新增请求、原生在途请求复用、模块自行请求去重、慢响应和空响应不重试、原生 429、页面/轨道延迟、早到响应、错误视频/语言、无字幕、模块异常、视频导航、用户字幕选择和桥接缺失。

浏览器验收步骤：

- 在 `chrome://extensions` 重新加载指向本项目 `dist` 的开发版扩展，再刷新 YouTube 页面，使新的 document_start 脚本生效。
- 打开一个有字幕、尚无本地摘要缓存的视频，立即点击总结；确认自动等待后继续生成，不需要手动开关插件。
- 分别在 YouTube 原生 CC 开启、关闭时重复，确认处理完成后状态与原来一致。
- 开启插件双语字幕的同时点击总结，确认两者都得到字幕，且播放器不会反复切换 CC。
- 获取期间快速切到另一个视频，确认不出现前一个视频的字幕或摘要。
- 在等待期间手动切换 CC 或字幕语言，确认插件不会把设置强制改回。
- 打开真实无字幕的视频，确认等待有上限，之后显示无字幕提示。

以上浏览器步骤尚未在本次环境中实际执行；自动化模拟通过不等同于所有真实 YouTube 页面均已验证。
