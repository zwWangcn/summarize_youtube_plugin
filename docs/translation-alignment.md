# 译文串句与清除缓存

## 本次样例的分析

用户确认原生英文字幕与声音同步，所贴英文的时间轴正确。样例中英文的 “They also, though, have an enormous private sector.” 对应的中文却是上一句的结尾“比如石油、航空、电信。”，之后华为／阿里巴巴、土地所有权、微信等内容也连续落后一条。优先怀疑译文跨 cue 搬移，而非对所有字幕施加了同一个秒数偏移。

“但个人和开发商可以租赁土地，工厂、房屋和公寓可以归私人所有”没有出现在所贴的对应英文中。可能来自未贴出的源字幕或上下文，也可能是模型补写；缺少原始字幕与模型响应，不能据此断定来源。

代码层面已确认：

- `transcript-translation.ts` 以一批固定 cue 和前后各最多 8 条上下文请求模型。提示词禁止拆分、合并、挪用邻句及翻译上下文，但这是对模型的约束，并非程序可验证的语义保证。
- `validateTranslationLine` 验证 JSON 字段、连续 cueId、非空译文，并拒绝模型返回的时间戳；调用方还验证完成标记。它不会检查中文是否完整、忠实地翻译了该 cue 的英文。编号连续但内容错位的输出仍可通过。
- `toTranslatedSegments` 使用返回的 cueId 查找本地原文并原样复用时间，不按中文句号重新切分或顺移数组下标。因而“语义放错 cue，但编号合法”会被绑定到错误句子的正确时间上，表现为中文字幕延迟。
- 播放器双语字幕和侧栏共用 cue 译文；坏结果可以存入 7 天缓存，刷新页面后继续复用。

以上证明存在接纳此类错位的缺口，但尚未拿到这个视频的原始 cue、AI 响应和供应商／模型，不能断言此次故障唯一由模型引起，也没有宣称修复语义对齐。若内部英文 cue 本身与声音不符，还需检查语义分段后的时间映射。

## 播放、翻译期间调整字幕样式

用户补充在生成字幕的同时调整过样式。当前保存路径是 `popup.ts` 的 `saveSubtitleStyle` → `setSettings({ subtitleStyle })` → `shared.ts` 的样式变更分支 → overlay 的 `setStyle`。保存仅写样式字段，接收端只设置字号、颜色、背景和宽度的 CSS 变量，没有重建 cue、改变时间戳、重排译文或重启翻译队列的操作。未发现样式单独导致持续串句的直接路径。

在 `translation-cache-reset.test.ts` 增加了翻译流尚未结束时连续三次调整样式的模拟：样式更新生效，请求没有被取消或重启，部分译文保留，最终译文及时间信息正常显示并缓存。该测试覆盖编排及存储事件，overlay UI 为模拟对象，尚未在真实浏览器复现用户此次操作，不能完全排除浏览器层面的异常。

另一个需要区分的行为是选中文字：`bilingual-overlay.ts` 的 `handleSelectionChange` 会在字幕文字被选中时冻结整块字幕，取消选区后显示最新 cue。这会使两行一起停留，通常不能解释英文继续同步、中文连续对应上一句的情况。模型串句仍是此前根据样例提出的假设，并非此次故障已确诊的原因。

## 清除功能

打开侧栏「原始字幕」，在字幕工具栏点击「清除本视频翻译缓存」。清除本视频所有语言、模型和流程版本的分段译文，同时重置当前页面的已完成译文、部分译文和失败状态。其他视频、摘要和设置保持原样。

清除前暂停当前视频的翻译队列和自动预取，取消在途翻译，等待旧 worker 的缓存写入结束，再删除持久化缓存。清除前开始的缓存读取会被版本检查拒绝，避免旧结果重新进入内存。若清除时切换视频，完成回调不会清空新视频的状态。存储失败会提示失败，不显示清除成功。

双语字幕开启时会按当前播放位置重新预取翻译；侧栏可再次选择「翻译本段」或「翻译全文」。这是一次重试机会，模型可能仍返回相同错误；清缓存也不改变原文分段及时间轴。

## 验证

自动化覆盖见 `src/service/translation-cache.test.ts` 和 `src/content/translation-cache-reset.test.ts`：精确的视频范围、不同语言／模型／旧版本、保留其他缓存及设置、内存和磁盘同时清除、重新翻译、取消流后迟到输出、写入竞争、迟到读取、清除失败、切换视频及双语字幕自动重新翻译。

浏览器验收（本次环境尚未实际执行）：

1. `npm run build` 后，在 `chrome://extensions` 重新加载指向 `dist` 的扩展，并刷新 YouTube 页面。
2. 打开已有译文的视频，在侧栏清缓存。确认旧译文消失，按钮恢复可用，点击翻译能生成新结果。
3. 双语字幕开启时清缓存，确认按当前播放位置自动重新翻译，侧栏同步更新。
4. 翻译途中清缓存，确认旧流停止；等待后刷新页面，确认不会恢复清除前的译文。
5. 清除途中切到另一个视频，确认新视频译文不受旧视频完成回调影响。
6. 对照原生英文、插件英文及中文记录故障片段，保留视频链接、起止时间和使用的供应商／模型，用于继续定位此次错位。
