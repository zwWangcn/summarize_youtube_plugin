# 1.5 开发与本地调试

工作分支：`codex/1.5`。扩展版本：`1.5.0`。

## 构建和测试版标识

```sh
npm run build:test
```

生成可直接加载的 `dist/`，无需保持开发服务器运行。Chrome 扩展管理页打开开发者模式，加载已解压的扩展程序，选择项目的 `dist/`。已加载过时点击该扩展的“重新加载”，并刷新 YouTube 页面。

开发构建的设置弹窗和视频侧栏标题区显示“测试版 1.5.0”。`npm run dev` 也默认显示标识。

正式构建：

```sh
npm run build
```

默认隐藏测试标识。构建时变量 `VITE_TEST_BUILD=true/false` 可以覆盖默认行为；可在 `.env.local` 中设置，参考 `.env.example`。修改变量后需要重新构建。发布前确保本地覆盖值没有设为 `true`；也可显式使用：

```sh
VITE_TEST_BUILD=false npm run build
```

这个变量控制测试标识和本地字幕诊断；字幕协议、网络请求和模型选择与正式版一致。

## 构建版脚本注入

`npm run build` 和 `npm run build:test` 将两个内容脚本构建为自包含 IIFE，Chrome 直接注入 `src/content/caption-main.js` 和 `src/content/youtube.js`，没有 `youtube.ts-loader-*.js` 或内容脚本的运行时模块导入。MAIN／ISOLATED 执行环境及原有权限保持不变。

`npm run dev` 的隔离脚本仍保留 HMR 加载机制；排查扩展资源跨源加载报错时优先使用 `npm run build:test` 的静态构建。更新后先重新加载扩展，再刷新视频。扩展管理页已记录的旧错误不会自动消失，可清空记录后观察是否有新错误。

## 字幕处理

1. 原始字幕在本地规范化，过滤独立及内嵌的 `[music]` / `[Music playing]` 等音乐标记；普通 music 单词和 `[NASA]` 等无关括号保留。清理会重映射保留下来的词及 run 坐标，不把音乐时间冒充为语音时间。查看原文和摘要不需要新的断句调用。
2. 根据原始字幕事件与现有分块预设创建稳定 section，模型分段不会改变其他 section 的编号。
3. 上传字幕（非 `asr` 轨道）保留每条原字幕的边界、内部换行及原始开始时间和时长，只翻译；自动生成字幕才允许模型重新分段。上传来源不是质量认证，当前策略优先尊重现成字幕。选轨在匹配音频／优先语言后，同语言优先选择上传轨道。
4. 按需请求目标 section，附带前后各最多 8 个原始字幕事件作为只读上下文。播放器优先当前块，默认在下一块开始前约 30 秒真实时间预取；根据最近 3 次翻译耗时（含重试）留出余量，提前量范围为 30–90 秒，并按播放速度换算为视频时间。以后一块真实开始时间为截止点，不依赖可能重叠的前一字幕显示时长。最多只预取当前块的下一块；命中缓存不调用模型，跳转时优先新的当前块并取消旧位置的预取。
5. 模型一次返回 `{"segments":[{"source":"原文摘录","translation":"译文"}]}`，自动字幕同时完成分段和翻译；上传字幕按数组中每个原始字幕字符串返回一条译文，客户端强制一一对应。没有逐词编号，也不接受模型时间。
6. 客户端从目标原文开头逐段消费，检查完整覆盖、不漏字、不重复。自动字幕匹配允许换行／连续空白、CJK 周围的可选空格、Unicode NFC 及直／弯引号等价；不会忽略英文单词分隔、大小写、数字或其他标点，也不搜索跳过不匹配的文字。最终原文及字符位置仍取自源数据。每个开始位置必须存在真实字幕事件开始时间或有效词／片段开始时间。缺少内部时间的文字通过 `keepTogether` 提示保持完整，不能用字符比例插值。
7. 自动字幕以 3–5 秒、中文译文约 16–24 字为目标；可读性参考原文 100 显示宽度、译文 64 显示宽度（中日韩字符按 2 计）和有足够文字时的词起始时间跨度。事件显示时长及尾部停顿不等同于讲话时长。过长结果最多尝试一次质量优化；优化失败保留已通过原文及时间校验的译文，不因长度拒绝整块。时间稀疏的跨度保留原粒度。显示结束时间仍采用原始时间依据，不声称恢复了词级发音结束时间。
8. 整块通过校验后才更新侧栏和播放器，部分响应不显示、不缓存。结构修复、网络重试及可选质量优化共享最多 3 次尝试预算。有结构／原文／时间校验失败时，最后一次尝试改用固定字幕单元：客户端确定原字幕事件边界，合并无可靠递增时间的相邻事件；模型只返回 `{"translations":[{"cueId":0,"translation":"译文"}]}`。客户端严格检查编号、数量和顺序，从本地补回原文并验证真实时间。上传字幕保持原边界。此备用路径牺牲部分语义断句自由度，避免原文回写失配持续阻断使用；不会增加三次之外的调用。备用结果与常规结果使用相同缓存和恢复路径。备用响应仍不合法时才提示重试；纯长度问题不会让有效译文失败。
9. 缓存保存分段范围、原文摘录和译文，绑定视频、源语言、字幕来源类型、模型、目标语言、源文字及时间指纹、chunk 预设和协议版本。恢复时重新严格对齐并构建时间。旧 1.4 缓存不复用，清缓存会清理同一视频的所有版本。

原文视图：未处理的块显示本地字幕，已处理且有匹配缓存的块显示模型分段后的原文。原文／译文切换不会发起额外调用。

旧规则断句引擎目前只留作本地回归对照，不再进入产品的字幕加载或翻译流程。

## 验证

```sh
npm test
npm run build
npm run build:test
```

建议在 YouTube 检查：只看原文没有 AI 请求；翻译本段只处理本段；双语字幕随播放切换；跳到远处不翻译中间所有块；切换原文和译文不重复请求；重新加载后恢复相同分段；清缓存、切模型、切语言和切分块预设不会恢复过期结果。

结构与时间正确性由测试覆盖，真实视频的语义断句和译文效果仍需用实际所选模型调试。

## 排错

UI 语言表随 JavaScript 打包，不从 YouTube 页请求 `chrome-extension://.../_locales/...`。原生 Chrome 本地化仍使用打包的 `_locales` 文件。

翻译失败会区分响应结构、原文覆盖、时间边界、字幕长度和上传字幕边界问题。控制台的 `[vas] Caption validation rejected` 包含失败块、尝试次数和具体原因；不再把这些问题一律显示成格式错误。处理协议升级会隔离旧的过长分段缓存。

测试版在字幕工具栏提供“导出字幕诊断”。发生校验失败后，即使后续自动修复成功，也会异步保留本地诊断：目标原始字幕与时间、前后文、各次响应、失败原因、模型标识和恢复结果。不会存储 API 密钥、自定义指令或完整提示词，也不上传诊断。所有视频合计最多保留最近 3 条，导出只包含当前视频 7 天内的记录。过期数据在下次写入时清理。异常大响应／原文会截断并标记；普通大小的记录可使用导出的目标 transcript、chunk 和响应离线重放匹配。正式版不记录，也不显示导出按钮。

更新后无需手动清空翻译缓存：处理协议版本已更新。重新加载扩展并刷新视频即可使用新协议。
